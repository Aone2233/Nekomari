Ordinary probes on legacy Agents may ignore v1.8 settings. The address-family
preference is a preference, not a fixed-family guarantee. Pinned probes have a
separate delivery protocol and support neither attempts, spacing, timeout, HTTP
mode, expected status nor IP preference. Existing pinned diagnostics report
eligibility for that protocol; they do not establish support for ordinary
probe options. No new capability-negotiation claim is made here.

The release workflow permits v1.8.1 under the manual-only policy: Agent binaries are
published as `manual-komari-agent-<os>-<arch>`, GitHub Latest remains v1.7.29 and the
Docker moving tags were not advanced. Exact-commit CI passed 8/8, release 10/10 and
Docker 2/2 before the tag. The theme gate was not closed: the owner excepted
confirmed third-party theme defects (see [COMPATIBILITY-V1.8.md](./COMPATIBILITY-V1.8.md))
and the remaining interaction checks stay open. The panel is deployed; no Agent was
upgraded, so no Agent-side fix above is running in production yet.
