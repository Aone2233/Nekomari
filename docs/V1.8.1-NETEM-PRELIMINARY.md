# v1.8.1 preliminary isolated netem evidence

Recorded 2026-11-12 (Asia/Shanghai). This is supplemental evidence, not closure
of the LAN calibration gate. A temporary Linux network namespace and veth pair
were used; no production interface was modified. The Agent's `icmpPing` path
performed 120 sequential probes per setting against the peer. The source veth
used `tc netem` egress random loss, and tcpdump independently captured replies
after the queue. Captures reported zero kernel drops.

The source-veth capture is after netem: dropped outgoing requests are absent,
so it independently checks received replies but cannot by itself prove the
number of attempted sends. The code invoked the production path 120 times;
this is not an independent sent-packet count. Captures and logs are currently
at `/tmp/nekomari-v181-netem` on the test host, not durable release artifacts.
The temporary namespace and veth were removed. An initial capture attempt was
incomplete because tcpdump was stopped before its buffer drained; the table
above comes from the subsequent complete run.

A retrospective 95% Wilson interval for the observed loss proportions contains
all configured values, but the interval was not specified in advance; it is
not a passing statistical acceptance. The repeat below addresses the
probabilistic test and independent counters; real LAN latency remains open.

## Predeclared isolated repeat

On the same date a fresh temporary namespace and veth were used for a new
experiment. Before running, the protocol fixed three runs of 120 production
`icmpPing` calls for each of 0%, 1%, 5%, and 20% netem egress loss, with no
retries or discarded runs. A `tc` egress action counted echo requests before
netem; tcpdump on the source veth counted replies. Each run required 120
counted sends, exact agreement between captured replies and Agent successes,
zero capture kernel drops, and inclusion of the configured loss probability
in a two-sided nominal 99.9% Wilson interval. The 0% run additionally
required zero observed loss. The wide intervals make this a coarse consistency
check; Wilson coverage is approximate, especially at boundaries.

| Netem loss | Agent successes / captured replies, three runs | Observed loss intervals (nominal 99.9%) |
| --- | --- | --- |
| 0% | 120 / 120 / 120 | 0–8.28% each |
| 1% | 120 / 118 / 117 | 0–8.28%, 0.23–11.10%, 0.46–12.40% |
| 5% | 113 / 115 / 116 | 1.82–17.16%, 1.07–14.85%, 0.75–13.64% |
| 20% | 93 / 95 / 93 | 12.55–37.00%, 11.32–35.18%, 12.55–37.00% |

All twelve runs met the predeclared checks, including 120 independently
counted sends and zero capture drops in each run. Protocol, counters, logs and
captures remain on the test host in `/tmp/nekomari-v181-netem-predeclared`;
the disposable network was removed. This improves the loss evidence, but it
does not verify a physical LAN or close the LAN latency acceptance gate.
