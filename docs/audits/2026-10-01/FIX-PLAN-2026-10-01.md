### F1b — 代码：把凭据从 URL 查询串移到请求头（发版）

**先纠正一个容易搞错的前提（我最初写错过，已核实）：** 服务端对 `Authorization: Bearer` 头的支持**只存在于 `/api/rpc2` 这条路径**（`web/rpc/jsonrpc/transport.go:215-219`）。而 agent 实际用的是 **`/api/clients/v2/rpc`**（`web/router/router.go:81-82`），它走身份中间件 `web/api/principal.go:33` → `web/api/Auth.go:168` 的 `extractClientToken`，**只读取 `?token=`、`?Authorization=` 两个查询参数和请求体里的 `token`，完全不读 HTTP 头**（`principal.go:20-21` 读 `Authorization` 头是给 **API Key** 用的，与 client token 是两套凭据）。

所以"只改 agent 侧"是**不够的**——那只会把泄露换个参数名（`?Authorization=` 一样会进 nginx 日志）。必须两侧都改：

**① 服务端：让 `extractClientToken` 也认头**（照抄 `transport.go:218-219` 的写法，保持向后兼容）
```go
func extractClientToken(c *gin.Context) string {
	token := c.Query("token")
	if token != "" {
		return token
	}
	// rpc2 约定: agent 经 ?Authorization=<token> 传入 client token（保留，兼容旧 agent）
	if token := c.Query("Authorization"); token != "" {
		return token
	}
	// 新增：Authorization: Bearer <token>。查询串会进 nginx/CF 日志，头不会。
	if auth := c.GetHeader("Authorization"); strings.HasPrefix(auth, "Bearer ") && len(auth) > len("Bearer ") {
		return auth[len("Bearer "):]
	}
	… 其余不变 …
}
```
**注意顺序**：查询参数必须仍排在前面。`principal.go:20-21` 会先用 `Authorization` 头去试 **API Key**（`isApiKeyValid`），败了才走到 client token；把 Bearer 头加进 `extractClientToken` 不改变这个次序，但**要确认 API Key 校验失败不会短路**（当前 `:21` 是 `if`，失败继续往下，安全）。

**② agent 侧：5 处拼接改为请求头**
```
agent/server/basicInfo.go:77   endpoint := … + "/api/clients/v2/rpc?token=" + flags.Token
agent/server/websocket.go:137  websocketEndpoint := … + "?token=" + flags.Token
agent/server/websocket.go:240  endpoint := … + "?token=" + flags.Token
agent/server/task.go:674       endpoint := … + "?token=" + flags.Token
agent/server/files.go:830      "/api/clients/v2/rpc?token=" + flags.Token
```
POST 走 `req.Header.Set("Authorization", "Bearer "+flags.Token)`；WebSocket 用握手头 `websocket.Dialer{HTTPHeader: http.Header{"Authorization": {"Bearer " + flags.Token}}}`。注意 `/transfer/:id` 那条也要一并改（`filemanager.AgentTransfer` 同样走这个中间件）。

**③ 过渡期**：服务端先发（同时接受两种方式）→ 再逐台升级 agent → 最后才谈脱敏。**在 9 台旧 agent 升级完成前，nginx 脱敏必须继续生效**，否则日志里仍会有 token。

**验收：** ① 用新 agent 打一台 canary，确认 `?token=` 不再出现在 `access.log`；② `deploy/install-node-agent.test.sh` 增加断言"生成的 unit 与命令行都无 `token=`"；③ 回归：旧 agent（v1.6.2）仍能正常上报。

## F3 P6-1 + P4-1：备份半成品与保留策略

### F3a — 代码：打包改成"临时名 → 校验 → rename"

**现状** `database/dbcore/dbcore.go:34-91`：`os.Create(dstZip)` 直接建正式文件名，`if walkErr != nil { return walkErr }` 时不清理。

```go
func zipDirectoryExcluding(srcDir, dstZip string, exclude map[string]struct{}) (err error) {
	tmp := dstZip + ".partial"
	out, err := os.Create(tmp)
	if err != nil { return err }
	// 失败就把半成品删掉：一个截断的 zip 与正常备份同名同形，只在需要回滚时才暴露
	defer func() {
		out.Close()
		if err != nil { _ = os.Remove(tmp); return }
		if cerr := os.Rename(tmp, dstZip); cerr != nil { err = cerr; _ = os.Remove(tmp) }
	}()
	… 原来的 Walk 逻辑不变 …
	if walkErr != nil { err = walkErr; return err }
	return nil
}
```
**注意两点，否则补丁会坏：**
- 必须**先把 `zw.Close()` 调完再 `os.Rename`**，否则 zip 的中央目录没写、rename 出来的是坏档。把 `zw.Close()` 从 `defer` 改成显式调用，并在它出错时走失败分支（原代码成功路径上 `zw.Close()` 被调了两次：显式一次 + defer 一次）。
- `out.Close()` 也要在 rename 之前完成；`defer` 里只留"删临时文件"的清理逻辑。

### F3b — 脚本：prune 不再因一个坏档停摆

`/usr/local/bin/prune-upgrade-backups.sh`（`set -euo pipefail`）中幸存者校验改为**跳过并告警**，且坏档改名保留以便取证：
```bash
  if command -v python3 >/dev/null 2>&1; then
    if ! python3 - "$f" <<'PY'
import sys, zipfile
bad = zipfile.ZipFile(sys.argv[1]).testzip()
if bad: raise SystemExit("corrupt entry: %s" % bad)
PY
    then
      echo "  WARN corrupt backup, renaming aside: $(basename "$f")" >&2
      mv -- "$f" "$f.corrupt"
      continue
    fi
  fi
```
（关键是把 python 放进 `if !` 条件里——条件上下文不受 `set -e` 影响。）

## F11 P7-3：GeoIP mmdb 更新的锁、超时与原子性

**现状** `utils/geoip/mmdb.go:134-165`：`s.mu.Lock()` 在 `:135`，唯一 `Unlock()` 在 `:162`，中间**五条早退全部持锁返回**；`http.Get` 无超时；`os.Create` 先就地清空线上文件。后果是任何一次下载失败都会让 `GetGeoInfo`（`RLock`）永久阻塞——包括 agent 基本信息上传的同步路径。本部署 `geo_ip_provider = "ipinfo"`，故潜伏。

**建议改动（把持锁段落抽成独立函数，让 `defer` 在 `initialize()` 之前释放）：**

> ⚠️ **我最初给的一版是错的，已修正。** `initialize()` 自己就取写锁（`mmdb.go:81-83`：`func (s *…) initialize() { s.mu.Lock(); defer s.mu.Unlock() … }`）。所以在 `UpdateDatabase` 里写 `defer s.mu.Unlock()` 然后 `return s.initialize()` 会**自死锁**——原代码在 `:162` 显式解锁、再调 `initialize()`，正是为了避开这一点。

```go
func (s *MaxMindGeoIPService) UpdateDatabase() error {
	if err := s.downloadToTempFile(); err != nil {   // 锁的作用域限制在这个函数里
		return err
	}
	return s.initialize()                            // 此处锁已释放；initialize 自己会取锁
}

// downloadToTempFile 持写锁完成下载、校验与原子替换。
func (s *MaxMindGeoIPService) downloadToTempFile() error {
	s.mu.Lock()
	defer s.mu.Unlock()                              // ① 所有早退都释放

	client := &http.Client{Timeout: 60 * time.Second}   // ② 超时
	resp, err := client.Get(GeoIpUrl)
	if err != nil { return fmt.Errorf(…) }
	defer resp.Body.Close()
	if resp.StatusCode != http.StatusOK { return fmt.Errorf(…) }

	if err := os.MkdirAll(filepath.Dir(s.dbFilePath), os.ModePerm); err != nil { return … }
	tmp := s.dbFilePath + ".new"                     // ③ 临时文件，不再就地清空线上库
	out, err := os.Create(tmp)
	if err != nil { return … }
	if _, err := io.Copy(out, resp.Body); err != nil { out.Close(); os.Remove(tmp); return … }
	if err := out.Close(); err != nil { os.Remove(tmp); return … }
	if err := validateMmdb(tmp); err != nil { os.Remove(tmp); return err }  // 至少非空且可打开
	if err := os.Rename(tmp, s.dbFilePath); err != nil { os.Remove(tmp); return … }
	return nil
}
```
**关键点：** `initialize()` 会重新取写锁，所以**必须**在调用它之前把锁放掉；用"抽函数 + defer"而不是"在同一个函数里 defer"，就是为了满足这一点。

**验收：** 用一个返回 500 的 `httptest` 服务器指向 `GeoIpUrl`，调用 `UpdateDatabase()` 得到 error，随后在 2 秒 deadline 内调用 `GetGeoInfo` 必须**正常返回**（当前会永久阻塞）；再验证失败后原 mmdb 文件**未被截断**（大小与内容不变）。
