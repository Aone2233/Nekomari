当前更值得做的是补齐**正确性、部署安全与回归覆盖**，而不是先调整 SQLite 连接池、全局采样频率或大规模重构。每项应拆成独立、可回滚的变更。

## 二、第一批：正确性与状态对齐

### 1. 发布列表缓存：分开记录成功时间与尝试时间

**依据：** `frontend/src/lib/releaseFeed.ts` 中，成功列表和失败尝试共用 `attemptedAt`。旧列表过了 6 小时有效期，刷新失败后，代码保留旧列表并将 `attemptedAt` 更新为当前时间；下一次读取因列表非空，仍按**成功缓存的 6 小时**判断。原本应在 15 分钟后重试的失败分支，可能把旧列表继续当作新鲜数据。现有 `frontend/script/release-feed.test.mjs` 只验证失败时返回旧列表，未覆盖失败后 15 分钟的再次请求。

**建议：**

1. 先补红灯测试：成功取 A → 6 小时后失败并返回 A → 15 分钟内不重复请求 → 15 分钟后重试并成功取 B。补充连续失败、无旧列表、并发去重及损坏缓存测试。
2. 分开记录“上次成功获取时间”和“上次失败尝试时间”。失败不能重置成功数据的 6 小时 TTL；仍按 15 分钟限制重复失败请求。
3. 明确现有 `nekomari.github.releases.v2` 缓存的迁移或废弃策略；不能信任未经校验的旧时间戳。
4. 在浏览器中复现 Workbox 行为：`frontend/vite.config.ts` 的 `^https://api\.` + `NetworkFirst` 可能在离线时返回过期的 GitHub API 响应，使应用误认为刷新成功。若证实，针对发布接口排除 SW 缓存或设专用策略；先排查其他 `api.*` 消费者，勿直接删掉整条规则。

**验收：** 时间推进测试通过；断网保留最后成功数据，但 15 分钟后可重试；网络恢复能显示新版本；在线/离线/恢复网络的浏览器行为有记录。SW 相关问题在复现前只称“风险”，不称线上故障。

### 2. 路线图与部署记录：区分已实现、已发布、已部署

**依据：** `CHANGELOG.md` 已列出 2026-09-25 的 v0.1.27：Agent 的 ICMP 非特权回退、重连退避与账本报错，以及面板拒绝混合地址族任务。`docs/ROADMAP.md` 和 `docs/DEPLOY-OC424.md` 顶部仍叙述 v0.1.26；路线图 A3 仍称认证测试 `-count=10` 不可重复，但 `.github/workflows/ci.yml` 已包含 `go test -race ./database/accounts ./web/api/public -count=10 -shuffle=on`。路线图 F1 仍把混合地址族任务创建策略列为待定，与 v0.1.27 变更日志不一致。

**建议：** 逐条核对 A3、E1/E3/E4、F1 与当前代码/CI，保留历史记录并标注完成日期。对 OC424 面板镜像、实际版本、备份、回滚镜像和各节点运行二进制版本建立证据表；无法连接的节点写“待核验”。提交历史只能证明发布，不能证明全量部署。部署文档保留 v0.1.26 的历史章节，新增经现场核验的记录，或明确标注当前状态未确认。

**验收：** 文档能一眼区分“仓库已实现”“CI 通过”“发布完成”“生产面板已核验”“Agent 节点已核验”；版本和哈希有来源，不凭推断补写现场结果。

## 三、第二批：Agent 凭据与权限

### 3. 先解决 token 的命令行暴露

`docs/ROADMAP.md` D1 与 `docs/DEPLOY-OC424.md` 均记录服务使用 `-t <token>`，同机用户可读取进程参数。此问题不会被 ICMP 回退自动解决。先盘点 systemd、OpenRC、容器及安装器生成命令的入口，选择受限配置/凭据文件方案；可保留旧参数兼容期，但新安装命令不得默认把 token 放在参数里。环境变量也可能通过进程环境或诊断输出泄露，不能只凭 `ps` 不显示就宣称完全安全。

**验收：** 先在一个可回滚节点验证服务连接；普通用户可见的进程参数、服务状态和常规日志不含 token；凭据文件权限、备份恢复及安装器文档一致。推广与轮换密钥需另列生产计划；报告不得输出真实 token。

### 4. 凭据方案稳定后再试点非 root Agent

v0.1.27 增加 raw ICMP socket 失败后的非特权 ping socket 回退，但能否生效仍取决于主机 `ping_group_range`、容器能力和服务用户。先选一个 systemd 节点，记录现有用户/能力/任务结果与回滚用 unit，再迁移为专用用户；验证 ICMP、TCP/HTTP、重连、基本信息上报、流量账本写入和重启后持久化。Alpine/OpenRC 与容器分别决策，不批量修改全网节点。

**验收：** Agent 确实非 root 运行；目标任务结果可与迁移前对照，数据目录可写，回滚能立即恢复。不可把单节点成功概括成全平台无需权限。

## 四、第三批：回归与可观测性

### 5. 先测管理页，再拆分大文件

`frontend/src/pages/admin/index.tsx` 约 2962 行。按 `docs/ROADMAP.md` A1 的顺序，先对节点表轮询、过滤、排序、选择建立**真实挂载态夹具**；现有服务端写路径测试不覆盖此页状态接线。测试在原结构下通过后，再按无行为变化原则拆组件，勿顺手变更交互/API。

**验收：** 拆分前后同一组挂载测试通过；覆盖乱序响应、请求失败后恢复和卸载再挂载；现有浏览器及面板 smoke 通过；顶层文件明显缩短，无新功能混入。

### 6. ICMP 权限失败要可见，但暂不改调度器

`docs/ROADMAP.md` E2 指出，显式 ICMP 任务遇到本地权限错误时，面板可能将其显示为目标丢包。v0.1.27 回退缩小了触发范围，但 raw socket 和 ping socket 都不可用时仍须说明。先评估节点级能力状态及其来源/更新时间，让界面区分“节点不能执行探针”和“目标不响应”；旧 Agent 未上报时显示“未知”，不能误判为“不可用”。

**验收：** 构造权限拒绝场景，界面显示原因而不伪装为目标丢包；老 Agent 兼容。调度器跳过任务是下一阶段独立决策，不能在本批静默改变覆盖范围。

## 五、性能项：先测量，再决定是否实施

- **Service Worker 首访：** `docs/ROADMAP.md` B1 记载过约 1.9 MB gzip、540 个文件的预缓存。用干净浏览器配置重新测传输量、路由块、二次访问和离线能力，再决定是否缩小 precache；这些是历史数字，不是本报告新测量。
- **边缘路径：** 对比源站、Cloudflare POP、浏览器资源和渲染耗时；改善建议须有前后采样、地区和时间窗口，勿把边缘波动归因于组件。
- **Agent 带宽与 SQLite：** 历史测量为每节点约 4–7 MB/天，目前没有连接池等待证据。先补可重复指标与阈值，暂不全局提高采样间隔或调大连接池。
- **人工验证：** 真实 OAuth 提供方、生产主题、屏幕阅读器和真实面板登录 smoke 应与 CI 夹具分开记录；CI 绿色不代表所有现场场景通过。
