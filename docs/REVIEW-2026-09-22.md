# Project review and dependency refresh - 2026-09-22

Baseline: clean `main` at `87df329`; original work branch
`codex/comprehensive-review-upgrade`. This is a local code and dependency review,
not a production deployment or a claim that every path is vulnerability-free.

## Scope and findings

Reviewed the route/identity chain, OAuth providers, upload and restore flow,
market download protections, agent updater, server lifecycle, existing metric and
resource hardening, frontend build, dependency manifests and CI. Existing full
server and agent suites supplied regression coverage beyond the manually read
paths. Production hosts and external OAuth accounts were not used.

| Priority | Finding | Result |
| --- | --- | --- |
| P1 | QQ callback accepted any returned state when the browser had a state cookie | Require exact equality; embed state in the aggregator callback URL |
| P1 | OAuth callback ignored the OAuth-enabled setting | Reject disabled OAuth before contacting providers |
| P2 | GitHub state never expired; provider states were reusable and unbounded | Shared 5-minute, 4096-entry store with atomic consumption and no cleanup goroutine |
| P2 | OAuth requests had no timeout/body budget and accepted unsuccessful responses | 15-second timeout, request cancellation on callbacks, 1 MiB response cap, status/token/identity validation |
| P2 | QQ errors could expose full upstream bodies or credential-bearing URLs | Return bounded generic errors; never include provider body or request URL |
| P2 | Invalid provider reload replaced/destroyed the working provider | Initialize replacement before publishing it |
| P2 | An incomplete archive merge deleted all successfully uploaded chunks | Keep the session on merge failure; successful finalization still cleans it |
| P2 | Dependency security advisories and stale compatible frontend releases | Upgrade affected Go modules and refresh npm lockfile within existing ranges |
| P3 | CI omitted existing lint and vet checks | Add both, plus Linux authentication race tests |

GitHub token requests now carry client credentials in the form body instead of
the URL. Generic providers reject null, empty and structured identities. Numeric
IDs deliberately retain the old float-to-string representation so existing SSO
bindings are not silently invalidated.

## Remaining work and release considerations

- QQ aggregators must preserve the supplied callback query. Verify the configured
  real provider before deployment; mismatches now fail closed. Existing OAuth
  attempts expire after five minutes and must be restarted after an upgrade.
- Generic numeric identity precision needs a binding migration before changing
  formatting. Prefer string IDs in provider configuration in the meantime.
- Follow-up implemented archive reservation limits: 16 sessions, 8 GiB total
  declared payload, 24-hour absolute expiry. Admission scans persisted sessions
  after restart and reclaims expired ones; hourly cleanup starts at bootstrap,
  including during first-install setup, and stops with the application.
  Writes and finalization use one non-queuing mutex; conflicts return 429.
  Frontend chunks are sequential, with a 120-second XHR timeout and 5/10/20-second
  retry backoff. Tests cover restart accounting, quota release, expiry, unknown
  directory preservation and cancel/merge/cleanup conflicts during finalization.
  The 8 GiB is a payload reservation limit, not a filesystem free-space guarantee:
  assembled archives, a current merge, metadata and downstream extracted files
  require additional space. Unknown store entries fail admission and are never
  automatically deleted. Only one process may own a store directory.
- The existing 27 frontend hook/refresh warnings remain. Recharts 2 and ESLint 9
  are deprecated; their major migrations require chart/UI and lint-rule review.
  Vite 6 and TypeScript 5 were not moved across major versions in this batch.
- Third-party OAuth end-to-end login, authenticated admin/editor workflows, Linux
  runtime, macOS agent, PostgreSQL integration and production performance were
  not verified in the initial local review. Publication and production verification
  are recorded separately in `DEPLOY-OC424.md`; this section describes local evidence.
- The earlier optimization review's database-pool deferral remains appropriate;
  this review adds no evidence for increasing SQLite concurrency.
