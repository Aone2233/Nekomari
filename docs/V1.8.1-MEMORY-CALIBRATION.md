# Default memory accounting comparison, 2026-11-15

An opt-in test called the candidate Agent's default `Ram()` function and
independently parsed `/proc/meminfo` immediately before and after. It checked
the `htoplike` definition and predeclared `max(1% of total, 4 KiB)` tolerance
against the midpoint of those reference readings. All three retained runs on
OC424 (Linux arm64) passed:

| Run | Agent used (bytes) | Reference before / after (bytes) | Difference (bytes) |
| ---: | ---: | ---: | ---: |
| 1 | 3,090,993,152 | 3,090,993,152 / 3,090,993,152 | 0 |
| 2 | 3,090,993,152 | 3,090,993,152 / 3,090,993,152 | 0 |
| 3 | 3,090,993,152 | 3,090,993,152 / 3,090,993,152 | 0 |

Total memory was 25,145,380,864 bytes; the tolerance was 251,453,809 bytes.
The test executable SHA-256 was
`66ea0032fcf28e3a6b702df6d1afeda12256bd6f6cdcce7dc566c49da6361003`.
The executable remains in `/tmp/nekomari-v181-memory-field-i0h5jz` on OC424.
Three local Linux x86-64 comparisons also passed under the race detector.
The reproducible, opt-in test is
`agent/monitoring/unit/memory_field_calibration_test.go`.

Both readers derive their numbers from the same kernel data, so this checks
the default function's interpretation on these hosts, not an independent
hardware meter. It does not cover other memory modes, swap, Agent scheduling,
network transport or Panel storage. No running service was changed.
