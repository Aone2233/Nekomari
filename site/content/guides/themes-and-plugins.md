# 主题与插件

## 主题

主题决定**访客看到的外观**（首页、节点详情、流量页）。面板自带一个默认主题，也可以在 **主题市场** 里安装其它主题。

### 换主题不会让后台消失

这是本分支相对上游的一个结构性变化：

**后台界面由面板自己提供，不再由主题负责。** 上游把后台入口交给主题实现，于是换一个没有实现后台的主题，管理员就进不去自己的面板了。本分支把后台独立出来，挂在 `/admin`，主题无法接管这个路径。

所以：**安装任何主题都不会影响你进后台。**

!!! note "主题的影响范围"
    主题控制的是访客侧页面。它**可以**自定义自己的后台界面并把入口指向 `/admin`，但面板的后台始终可用。

### 背景图与视频

主题设置里可以配背景图（区分浅色/深色、桌面/移动）或桌面视频。这些设置指向**主题自己的资源路径**。

!!! warning "主题升级可能让背景消失"
    背景图是**上传到已安装主题目录里**的资源，通常不在主题源码中。用源码重建主题并整体替换安装目录，会把这些手工加入的文件一并删掉 —— 页面背景随之变空，而日志里没有任何线索。

    如果背景图对你重要：**升级主题前备份主题目录**，或在升级后重新上传。观察到的现象是"背景没了、控制台一个 404、其它一切正常"。

### 缓存

主题的非哈希资源（背景图等）曾拿到过长的缓存头，导致**一次短暂的 404 被边缘缓存下来**，之后即便文件已就位，浏览器里仍然是空白，直到硬刷新。

现在这类资源会声明"每次协商"（`no-cache` + ETag），构建产物（文件名带内容哈希）才给长期缓存。遇到"文件明明在但页面不对"时，先硬刷新一次。

## 插件

插件扩展面板的能力：通知通道（Telegram、Bark、邮件、Gotify、Server 酱³……）、DDNS、开放 API、备份等。

### 版本门槛

每个插件在清单里声明它要求的服务端版本（`komari` 字段，例如 `>=1.6.0`），**面板与服务端两端都强制**。不满足时面板不显示安装按钮，服务端也拒绝加载。

本分支的版本号从 `1.6.0` 起**接续上游编号**，正是为了让继承来的插件市场能识别它 —— 早期用 `0.1.x` 编号时，官方市场 19 个插件里有 15 个装不上。原因见[与上游的关系](../introduction/lineage.md#version-numbering)。

### 装一个插件

**插件市场** → 选插件 → 安装。安装后可开启并配置（通知类插件通常需要在配置里填 API key 或 webhook 地址）。

!!! warning "第三方插件未经审查"
    面板在插件市场顶部就这么写着：插件代码在面板进程内运行，**等价于给了它面板主机的执行权限**。装之前确认来源，优先用官方市场的插件。

### 插件装不上 / 加载失败

| 现象 | 原因 |
|---|---|
| 没有安装按钮，提示需要更新 | 版本门槛不满足。看面板版本是否 ≥ 插件要求 |
| 装上了但没生效 | 插件装好后需要**开启**，部分还需要启用其公开页面或路由 |
| 加载时报错 | 插件可能用到了本分支基线上没有的 API。版本门槛是版本比较，**不是能力检查** —— 见下面的说明 |

!!! note "版本门槛的残留风险"
    要求 `>=1.6.0` 的插件可能用到上游在 `1.6.0-pre1` 里新增、而本分支基线（`1.5.0-fix1`）没有的 API。这种插件会**通过版本门槛但在加载时失败**。

    要真正判断兼容性，只能读插件源码。发现不兼容时，正确做法是提高那个插件在索引里的版本要求、或补上缺失的 API，而不是降低面板版本号。
