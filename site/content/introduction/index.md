# 介绍

Nekomari 是一个**服务器监控系统**：一个中心面板，加上每台被监控主机上的一个探针（agent）。

探针定期上报指标到面板，面板存进内置的时序库、渲染图表、按规则告警。它没有外部依赖 —— 不需要 Prometheus、InfluxDB 或消息队列，一个二进制或一个容器就是全部。

## 它适合什么场景

- **少量到中等规模的机群**（本分支的实际使用规模是十几台），你希望一屏看完所有节点的状态
- **需要长期留存与回顾**：SLA 报表、流量趋势、按月的账单估算
- **不想为了监控再养一套基础设施**：单容器部署，指标落在本地 SQLite

如果你的规模在数百台以上，或者已经在用 Prometheus / VictoriaMetrics，Nekomari 的定位会更偏向"轻量聚合与展示层"，而不是替代它们。

## 架构一览

```
        ┌──────────────┐   WebSocket（探针 → 面板长连接）
        │   面板        │◀───────────────────────────────┐
        │  (单容器)     │                                │
        │              │   HTTP 上报（指标 / 基本信息）   │
        │  SQLite 指标库│◀───────────────────────────────┤
        └──────┬───────┘                                │
               │ 下发任务（exec / ping / 升级 / 终端）    │
               └────────────────────────────────────────▶ 探针（每台主机一个）
```

两条通道是分开的，这一点影响排障方向：

- **上报**走 HTTP，探针推到面板。这条挂了，面板上就看不到数据。
- **下发**走 WebSocket 长连接。这条挂了，数据照常上报，但远程执行、终端、面板触发的升级都不工作。

所以"节点在线但点不动"和"节点离线"是两个不同的问题，排查入口也不同。
