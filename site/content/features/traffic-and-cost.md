# 流量与成本

这一块解决的是"这个月还剩多少"和"这些机器一共花多少钱"，两者都容易算错。

## 实时带宽与累计流量

首页顶部是**实时带宽**与**累计流量**。这里有一个必须知道的单位问题：

探针上报的计数器来自内核，是**自开机以来**的累计值。如果直接拿它和套餐额度比，会得到一个荒谬的数字 —— 一台开机三个月的机器，计数器是三个月流量之和，面板用它除以月额度就会显示"已用 800%"。

所以节点上要配置**月度重置**（安装脚本的参数 `--month-rotate <日>`），让探针上报"本月从第 N 天起"的流量。这样面板的百分比才有意义。

!!! warning "换月日要按服务商账单日设置"
    大多数服务商的计费周期不是自然月。设错日期，百分比会在账单日前后出现跳变。

## 账单与资产概览

节点可以填：

| 字段 | 用途 |
|---|---|
| 价格与周期 | 月付 / 季付 / 年付 / 一次性 |
| 到期日 | 驱动到期提醒 |
| 流量额度 | 驱动流量告警与预测 |
| 带宽 | 展示用的标称带宽 |

**资产概览**把它们汇总：在用节点数、折合月/年成本、即将到期的机器。

## 成本预测

**流量与成本预测**按当前速率外推：

- 到重置日为止会不会超量
- 按当前使用节奏的月度/年度成本

它给的是**趋势判断**，不是承诺。用量波动大时（例如刚跑过一次大流量任务），外推会明显偏高 —— 这也是它有用的地方：它假设"当前速率持续"，而这正是你需要在超量前知道的事。

## 常见问题

??? question "流量数字和 `vnstat` / 服务商面板对不上"
    检查两件事：**换月日**是否和服务商账单日一致；以及网卡排除列表（`--exclude-nics`）是否覆盖了 `docker0`、`lo` 这类本地流量。容器流量会被重复计算，通常应该排除。

??? question "带宽曲线有缺口"
    曲线缺口意味着那个时间段面板没收到数据。先看节点是否离线过，再看探针日志里的上报失败记录 —— 面板不会平滑填补缺口，因为"没有数据"和"数据为零"是两件不同的事。
