# 运维能力

这些功能依赖**下发通道**（WebSocket 长连接）。如果节点在线但下面这些按钮点不动，看[这里](../get-started/quick-start.md#confirm-online)。

## 批量执行

在多个节点上跑同一条命令，逐节点看结果。用于收集信息（`df -h`、`systemctl status`）或做小范围变更。

!!! warning "它不是配置管理工具"
    批量执行**没有**幂等语义、没有回滚、没有并发上限之外的保护。它是一条命令发给多台机器。需要"结果必须一致"的变更，仍然应该用 IaC 或配置管理。

    经验做法：先用它在**一台**上验证命令，再框选其余机器。

## 终端

浏览器的交互式 shell，基于 WebSocket。适合"看一眼那个配置"，不适合长时间作业 —— 页面关掉连接就断了。

## 会话与远程执行记录

执行的命令与终端会话会留档，可以回看是谁在什么时候对哪台机器做了什么。

## 配置导入导出

把面板配置（节点分组、告警规则、通知通道、主题设置等）导出成文件，在另一个实例导入。用于：

- 迁移到新面板
- 变更前留档，出问题可对照
- 把一套规则复制到测试实例

导出内容**包含凭据类字段**（token、webhook key），按密钥对待。

## 探针升级由面板下发 { #agent-upgrade }

面板可以告诉节点运行**指定版本**的探针，而不只是"升到最新"：

| 动作 | 效果 |
|---|---|
| 指定版本 | 该节点运行你给的版本。**可以指向更早的版本**，这就是回滚 |
| 清除指定 | 该节点恢复跟随最新发布 |

每个节点的结果会分别报告：`dispatched`（已下发）、`at_target`（本来就在该版本）、`offline`（未连接，请求没送到）、`failed`（下发失败）。**这四种要采取的动作不同**，所以面板不合并成一个"成功/失败"。

!!! note "目标会重复下发"
    面板下发时会重新发送目标版本。这不是冗余：**升级过程中重启的节点会丢失内存里的目标**，不重发的话它会恢复"跟随最新发布" —— 悄悄把这次回滚撤销掉。

### 一个必须知道的边界：引导 { #bootstrap-limit }

**面板不能升级一个还不理解"指定版本"这项指令的旧探针。** 那个能力首次出现在 `v0.1.45`；更早的探针（包括 `0.1.x` 系列）需要**直接替换二进制**才能进入这套机制。

换句话说：**任何一项新的探针能力，第一次铺开都必然是手动的。**

## 权限

上面这些都属于管理员能力。给他人账号时按最小权限授予 —— 终端与批量执行等价于该主机上的 shell 权限。
