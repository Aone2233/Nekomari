# 监控与告警

## 指标采集

探针按**上报间隔**（默认 10 秒，参数 `info-report-interval`）推送指标，面板写入内置的 SQLite 时序库。指标名是 Prometheus 风格，例如：

| 指标 | 含义 |
|---|---|
| `cpu.usage` | CPU 使用率 |
| `net.total.up` / `net.total.down` | 累计网络吞吐 |
| `ping.latency_ms` | Ping 时延 |
| `ping.loss` | 丢包率 |

数据有分层降采样与保留策略，长时间留存不会把磁盘吃满。

!!! note "为什么有些指标要等一会儿才有"
    累计型指标（如流量）需要一个时间窗口才能算出速率。刚添加的节点会在第二个周期后才有曲线。

## 多线路 Ping

每个节点可以配**多条独立的 Ping 任务**，用来区分"目标不通"和"这条线路不通"。支持三种探测方式：

| 类型 | 用途 |
|---|---|
| **ICMP** | 最接近"网络是否可达"的答案 |
| **TCP** | 绕过 ICMP 被封的情况，探测到具体端口的握手 |
| **HTTP** | 端到端可用性，含状态码 |

### 一个必须知道的限制：ICMP 需要权限

ICMP 探测要开 raw socket。**探针以 root 运行时没问题**，但如果它以普通用户运行（例如 systemd 用户级单元，或为了最小权限而降权），就必须满足以下之一：

```bash
# 给二进制文件能力（推荐，随二进制走）
sudo setcap cap_net_raw+ep /path/to/komari-agent-linux-amd64

# 或放宽非特权 ping socket 的取值范围
sudo sysctl -w net.ipv4.ping_group_range="0 2147483647"
```

两者都没有时，**探针会明确记录它无法发出 ICMP**，面板也会在该节点上给出警告：

> 该节点无法发出 ICMP 探测：裸 socket 与非特权 ping socket 都打不开。此节点上的 ICMP 任务显示的丢包是工具的限制，不是目标的行为。

!!! warning "这条警告值得认真对待"
    它出现时，该节点上 ICMP 任务报出的**丢包数字是假的** —— 那是工具发不出去包，不是目标不回。面板明知这一点还显示数字，所以用徽章明确标注。

    **一个容易踩的坑**：`cap_net_raw` 是**文件属性**。用 `cp` 或 `install` 替换探针二进制会**丢掉它** —— 两者都只复制内容和权限位，不复制扩展属性。所以**任何不经升级脚本的二进制替换都要重新执行一次 `setcap`**，回滚到旧二进制也一样。

## 告警

支持的事件类型：

| 告警 | 触发条件 |
|---|---|
| **离线** | 节点超过阈值没有上报 |
| **负载** | CPU / 内存 / 磁盘超过规则 |
| **流量** | 周期内用量超过额度 |
| **到期** | 账单到期日临近 |
| **SLA 违约** | 可用性低于设定目标 |
| **流量预测** | 按当前速率预测将在重置前超量 |

通知通道：Telegram、Bark、邮件（SMTP）、Gotify、Server 酱³、Server 酱 Turbo，以及通用 Webhook。通道在插件的通知体系里实现，**插件市场**里可直接安装。

## 维护窗口

计划内维护（重装系统、迁移、带宽调整）期间不希望收到告警时，创建**维护窗口**：在指定时间范围内抑制该节点（或分组）的告警。

窗口结束后告警自动恢复，不需要手工开关。

!!! tip "维护窗口和静音的区别"
    静音是"我现在不想看"，维护窗口是"这段时间的异常是预期的"。后者会记录在案，所以在回顾时能区分"真的没事"和"当时在维护"。
